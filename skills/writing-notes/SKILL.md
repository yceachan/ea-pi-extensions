# writing-notes

写笔记不只是记录，更是对知识的**结构化整理**。本技能提供一套写作纲领，确保每篇笔记结构一致、渲染可靠、知识可追溯。

本技能负责**笔记的宏观结构与格式规范**。

## 写作流程

每篇笔记按以下顺序推进：

1. **确定主题与范围** — 一句话说清这篇笔记要回答什么问题。
2. **Top Level Insight/Abstract** — 以行业专家的深刻洞察，用一段话，明晰中心话题，高屋建瓴。
3. **搭建层级骨架** — H2 一级章节 → H3 细节，确保层级纪律（见 §四）。
4. **撰写正文** — 在骨架中填入内容、代码块、图表。
5. **标注引用** — 实际参考过的资料才列入 Ref 块（见 §三）。
6. **自检** — 检查 frontmatter 是否合规、mindmap 是否覆盖全文章节、引用是否完整。

## 一、YAML Frontmatter 规范

这是 VitePress / Obsidian / 多数 md 渲染器正确解析元数据的**基础**。写错一条就会导致整个 frontmatter 被当作普通段落原样输出。

### 硬性规则

1. **文件第一行必须是 `---`**。前方不允许有任何空行、BOM、空格、注释。前导空行会让大多数渲染器识别不到 frontmatter，整块 YAML 会裸露在正文中。
2. **YAML 闭合 `---` 前留 1 个空行**，将元数据字段与闭合符在视觉上隔开。
3. **YAML 块结束后留 2 个空行**，再开始正文（H1 标题或 mindmap）。

### 必须字段

| 字段     | 格式                       | 说明                                   |
| -------- | -------------------------- | -------------------------------------- |
| `title`  | 字符串                     | 笔记标题，与 H1 呼应                   |
| `tags`   | YAML 数组 `[tag1, tag2]`   | 用于分类和检索                         |
| `desc`   | 一句话字符串               | 笔记概要，用于索引和搜索摘要           |
| `update` | `YYYY-MM-DD`               | 最后更新日期                           |

### 模板

```markdown
---
title: <name>
tags: [tag1, tag2, tag3]
desc: <one sentence>
update: yyyy-mm-dd
---

# H1 Title

> [!note]
> **Ref:** [web source](url) | [local source]($Workspace/path)

正文...
```

## 二、Top Level Insight

### 2.1 Abstract

问题背景，必要性，本质，边界范围，以行业专家的深刻洞察，用一段话，明晰中心话题，高屋建瓴，遵循全局行文纪律。

## 三、引用规范

### 引用块格式

在 H1 标题下方、正文（或 mindmap）前放置引用声明：

```markdown
> [!note]
> **Ref:** [来源名](url) | [来源名]($Workspace/path)
```

### 引用原则

- **只列实际参考过的资料**。不堆砌链接，不编造引用。
- **本地引用使用相对路径**，便于笔记在不同环境间迁移。
- **外部链接优先使用官方文档**，其次才是博客/教程。
- 如果笔记没有参考任何外部资料，可以省略 Ref 块。严禁为了形式而编造。

## 四、层级纪律

- **H1 唯一**
- **H2 是知识模块**：一个 H2 承载一个独立的知识主题。
- **H3、H4 是细节展开**：具体概念、代码示例、对比分析。

## 五、行文纪律

写作前先想清楚这篇笔记是**给谁看、什么时候看**的。

| 维度         | 架构全景文档                                   | 认知札记笔记                                                 |
| :----------- | :--------------------------------------------- | :----------------------------------------------------------- |
| **目的导向** | **呈现、对齐、交付**：让用户快速获得共识性全貌 | **思考、内化、涌现**：促进深度理解和创意连接                 |
| **结构特征** | 强结构化                                       | 原子化、松散网络，强调概念间的**水平链接**，结构是自发生成的 |
| **内容性**   | 对已知结论的结构化整理。                       | 对既有话题的导入，深化                                       |

- 行文严谨，务实，避免口语化表达，避免重复阐述
- 叙事逻辑自洽，结构合理，内容详实，What , Why , How 系统化分析思考。

1. **禁止出现以下任何句式或词汇**：
   - “不是……而是……”
   - “咽喉”、“解剖”、“落地”、“闭环”、“赋能”等避实就虚的无意义辞藻。
2. **如果一句话能说清，就只写一句**。不要为凑长度而扩写。
3. 写完逐句检查：确保每个词都承担着应有的信息量。

**自检清单**：

- 整改所有反模式句式词汇。
- 删除所有不必要的比喻或用力过猛的修饰。

## 六、Illustration

一图胜千言，积极地考虑引入图示辅助解释机制，评估所需图示的复杂度，以复杂度递增依次考虑如下绘图手段

- **TEXT FLOW**：绘制简单连线，线性层级时，考虑TEXT FLOW即可

- **[[writing-mermaid]]** ： 简单mermaid自行编写，对于复杂mermaid(80行以上代码),委托子代理编码并使用`mmdc` cli工具来校验，交付后再交由视觉模型评估质量。使用此SKILL指导所有 Mermaid 图表的语法细节、类型选择、编码规则（`""` 包裹、禁用 `;`、`autonumber`、`rect rgb` 高亮通道等）和自检清单均由此技能统一管理。本技能中涉及图表的绘制均委托给它。
- [[**drawio-skill**]]：重型框架机制，电路等特殊领域建模，可视化效果为首要追求目标，文本化结构不好表达预期图例，当遇到这些复杂情景时，积极委托子代理使用drawio-cli 生图，并交由视觉模型评估质量。
